# Architecture and technical notes

How the site works inside, how to extend it, and the deploy and analytics details. For an overview, setup and commands, see [`README.md`](README.md).

## How it works

- **Data flow**: the build finds every language folder under `src/content/sentences/` (`lib/content-langs.ts`, `getContentLangs()`) and flattens each one into `/data/<contentLang>/sentences.json` (`lib/sentence-corpus.ts`, which fails the build on a path mismatch or a duplicate id or text). The home page passes the list of content languages and the starting one (the interface language when it has sentences, otherwise the default language, otherwise the first folder) to the island. The island fetches it on load, filters by category and difficulty, and draws sentences from a shuffled queue that never repeats until the pool is exhausted.
- **Home page controls** (`features/typing-test/TypingTest.svelte`, `clock.ts`): the home page controls in one view: **one row** of sentence language, mode, duration or count, and Filter; then, in Time mode only, the **progress bar**; then the **typing box**; then the **mode description**; then the **Restart** row with its `Esc` hint (mouse devices only). Narrow screens use these steps, in order (tight spacing, language code and short mode names, icon Filter button, wrapping only as the last resort; measured in Chromium: one row at 390 and 360 px in every mode, at 320 px one row except Time, where Filter drops to a second line). The parts, in detail: (1) **mode**: a native `<select>` (`aria-label` `test.modeLabel`, no visible label) with every mode from the registry in `test-modes/index.ts` (`MODE_IDS`: Time, Sentence, Count, Relaxed, Own text; a mode added to the registry appears in it with no other change). It starts on **Time on every page load** (the choice is not remembered, so no storage key and the privacy text are unchanged). Changing the mode starts a new test **and keeps the focus on the select** (`updateSettings(patch, false)` skips `typingArea.focus()`), so a keyboard user can keep browsing the modes with the arrow keys; the price of the select is two taps to change the mode (accepted trade-off). `ModePicker.svelte`, the "More" disclosure and `MAIN_MODE_IDS`/`MORE_MODE_IDS` were removed; the dictionary keys `moreModes`, `durationCaption` and `countCaption` and the `.segmented` / `.segment` CSS went with them. (2) **Duration or count** (Time and Count only): a native `<select>` like the mode, no visible label. In **Time** the options read `mm:ss` (`00:15`, `00:30`, `01:00`, `02:00`; option values are the seconds; default **00:30**, the existing default of `durationSec`) through the pure `formatClock(seconds)` in `features/typing-test/clock.ts` (tested; the running readout reuses it); `aria-label` `test.durationLabel`. In **Count** the options show **only the number** (1, 3, 5, 10; the select has to stay narrow to fit the one-row layout; the full text, `test.countOptionOne` / `test.countOption` with `{count}`, is the option tooltip) and the select is named by `aria-label` `test.countLabel`. Like the mode select, a change starts a new test **and keeps the focus on the select**. Kalimat, Santai and Own text show neither select. **Time readout** (`data-testid="time-readout"`, `role="timer"` with `aria-live="off"`, so it is not announced every second; the live region still gives the coarse countdown and the result): in **Time** mode, once the test runs (`status` `running`, after the first key) the countdown `mm:ss` (`getRemainingSeconds` in `clock.ts`, rounded up, tested) replaces the duration select **in the same box**: both sit in one grid cell (`.readout-slot`), the select stays in the layout but is hidden (`visibility`, so it is not focusable and not announced), which gives the countdown exactly the size of the select and shifts nothing. On `ready`, `finished`, Retry and Esc the select is back with the chosen duration; the duration cannot be changed midway. **Sentence** and **Own text** (while a text is typed, not in its editor) show the elapsed time (`getElapsedSeconds`) as a read-only item in the controls row from the start (`00:00`); **Count** shows it in a small line right below the row (with the count select it would not fit one row at 360 px, measured; the one-row layout wins). **Relaxed** has no readout (`showsClock: false`). The old "Time left" line and `data-testid="clock"` are gone; the dictionary keys `test.timeLeft` and `test.elapsed` are now the readout names (`aria-label`). **Progress bar** (`.time-bar` and `.time-bar-fill` in `global.css`, `data-testid="time-bar"`): in **Time** mode only, right above the typing box (8 px high, `aria-hidden="true"`: it is decorative, the numbers are in the readout). It is full on `ready` and shrinks to empty as the time runs; it is rendered from `ready` on, so nothing moves when the test starts, and it goes with the typing box when the result appears. The fill is as wide as the track and slides left inside it (`translateX`), so its border is never stretched: light mode has the 2 px `on-primary` border the design rules require for a `primary` fill, dark mode has none (`primary` is 10:1 on the surface). `TypingTest` passes two custom properties from the pure `getTimeBarFraction(durationSec, remainingSec)` (`clock.ts`, tested): `--bar-now` (share of time left now) and `--bar-next` (one second from now). While the test runs the fill moves to `--bar-next` over 1 s, linear, so it glides; at rest it shows `--bar-now` with no transition, so Retry and Esc snap it back to full. With `prefers-reduced-motion` it shows `--bar-now` and only steps once per second. It follows the 100 ms tick of the clock, so it can lag the real time by up to 100 ms. **Mode description** (`ModeDescription.svelte`, `data-testid="mode-description"`, dictionary `test.modeDescriptions`, one sentence per mode in both languages): a `caption` line in `text-muted`, **always visible** and not live (it only changes with the mode, which the select announces), right under the typing box and above the Restart row with its `Esc: restart` hint (Time, Sentence, Count and typing Own text, in `TypingTest`), under the typing box of **Relaxed** (`RelaxedSession`) and above the hint in the **Own text editor** (`CustomTextInput`); not shown on the result screen or the Relaxed summary (no typing box there). To avoid saying things twice, `test.hint` is now only "Tap the text and start typing." (the Esc part is the keyboard hint's job) and `relaxed.hint` and `customText.hint` keep only what the description does not say (nothing is recorded; mistakes do not block; Esc restarts the sentence; the result never counts as a personal best). (3) **One row** (`.controls-row` in `global.css`, `data-testid="controls-row"`): the controls are **sentence language, mode, duration or count, Filter**, in that DOM and visual order, directly above the typing box (the running readout is described above). Every control keeps the 44 px height and takes only the width of its content (`flex: none`). **Narrow screens, in order:** (1) tighter spacing (0.5 rem gap, `.field-compact` with 0.375 rem side padding); (2) the sentence language shows its **short code** (`ID`, `EN`, `PT`; `ContentLangSwitch` prop `compact`: the code is the text of each option, the full name is the option and select `title`, the select keeps its `aria-label`; the settings, collection and statistics pages still show full names) and the mode options use the short names `test.modesShort` (Indonesian "Teks" for Teks sendiri, English "Text" for Own text; full names are tooltips); the count select shows numbers only (see above); (3) the **Filter** button is an icon (inline SVG funnel) plus the number of active filters, with `aria-label` "Filters (2)" and `title`; (4) **last resort, approved 2026-11-05**: the row has `flex-wrap`, so it wraps only when the controls cannot fit. Measured with Chromium (390, 360 and 320 px, Indonesian and English, all five modes, Count at 10): one row at 390 and 360 px in every case; at 320 px one row in every mode except **Time**, where the Filter button drops to a second line (right aligned). No horizontal page scroll at any width. `controls.spec.ts` checks one row at 390 and 360 px in every mode. The sentence language is hidden when only one language exists. The **Filter** button (`aria-expanded`, `aria-controls="filter-panel"`) counts the active filters: a category other than All, a difficulty other than All, and weak-key practice on. Its panel is **closed on every page load** (the open state is not saved), opens in the page flow (it pushes the typing box down, only because the user asked) and holds the category and difficulty selects, the difficulty hint and the **Practice weak keys** button with its note. Esc inside the panel, or on its button, closes the panel only. Own text hides the whole Filter button; Relaxed keeps it without the practice button (rules unchanged). No positive `tabindex`. Tests: `tests/e2e/controls.spec.ts` plus the shared helpers in `tests/e2e/helpers.ts` (`chooseMode(page, mode, ui)` is one `selectOption` on the mode select, `chooseDuration(page, seconds, ui)`, `chooseCount(page, count, ui)` (switches to Count first), `modeSelect`, `durationSelect`, `countSelect`, `openFilters(page)`, `contentLangSelect(page)`): use them in any new spec instead of clicking the controls directly.
- **Typing area** (`typing-area`): a presentational component. It receives the typing state (`typingState`) and reports changes through `onInput(value)` and `onEscape()`; it owns no test logic. It shows one `span` per character in Lora (`font-typing`): pending `text-typing-pending`, correct `text-typing-correct`, incorrect `text-error` with an underline and a tint (never color alone, so a mistyped space is visible too). The caret is a 2 px `accent` pseudo-element that blinks gently and does not blink under `prefers-reduced-motion`; its look (`line`, `block`, `underline`) and the text size (`sm` 1 rem, `md` 1.25 rem, `lg` 1.5 rem, always four lines high) come from `settingsStore` (`caretStyle`, `fontSize`). The box is a `surface` card with a 2 px `border`; because the real input is invisible, the 2 px `accent` focus ring is drawn on the box with `focus-within`. It keeps the caret scrolled into view, blocks paste, and keeps the transparent input in sync with the state (a restart clears it). `focus()` is exported so the parent can focus it when a test starts. **Focus lost:** when the input blurs (for example the virtual keyboard was closed, or the window lost focus), the component waits 150 ms (so a click on a nearby button does not flash it), then blurs the text (`filter: blur(6px)`, instant under `prefers-reduced-motion`) and shows a full-box `button` with the text `test.focusLost` ("Tap to continue"). A click or tap on it, or any key press while nothing else has focus (the page body), calls `focus()` and removes the overlay; a keyboard user who tabbed to a chip or select keeps control of it, because keys are only taken over when the body is focused. The timer is never paused. The overlay is placed after the input, so the markup `box > text div + input` that the e2e selectors rely on is unchanged. Relaxed mode and custom text reuse it.
- **Engine** (`typing-engine`): pure functions with no DOM or timers. `applyInput` takes the full input value and counts only newly added characters as keystrokes, so erased mistakes still count towards accuracy. Its third argument `{ stopOnError }` implements **stop on error**: the first wrong character is kept and counted as an error, but nothing typed after it is accepted until it is deleted (`findFirstError` finds it). `getProgressLength(state, stopOnError)` is what the modes see as progress: with the option on, a wrong last character does not count, so a test can never end on a mistake. **Accented input:** target texts are Unicode NFC, but an accented letter reaches the input either as one character (`e` with acute, U+00E9) or as a base letter plus a combining mark (`e` + U+0301; common on macOS, Android and input methods). `applyInput` normalises the value to NFC first (`normalizeInput` in `accents.ts`), so both forms give the same text, length and keystroke count, and `TypingArea` writes the NFC text back into the field whenever it differs (the field and `typed` never drift apart). When a mark arrives as its own event after the bare letter (`isAccentMerge`: same length, only the last letter changed, base letter plus accent), it corrects the last keystroke: no new keystroke, and the error count (and the key statistics, `tallyKeystrokes(..., previousTyped)`) follow whether the corrected letter is now right. A **dead key or input-method composition** (`compositionstart` to `compositionend`) is not counted while it is open: `TypingArea` ignores the provisional `input` events (`shouldDeferInput` in `composition.ts`), does not rewrite the field during the composition (that would cancel it), and sends the final value once on `compositionend` (Safari may fire one more `input` after it; the repeated value adds nothing). A key press that belongs to an input method (`isComposingKey`) never triggers Escape, so Escape cancels the composition, not the test. Covered by `accents.test.ts`, `composition.test.ts` and the e2e `accents.spec.ts` (language `es` set through `localStorage`; a real keyboard layout or phone is a manual check, see "Adding a sentence language", step 8).
- **Metrics**: one word = 5 characters. WPM counts correct characters only, raw WPM counts everything. Accuracy is the share of correct keystrokes. Consistency is `100 - coefficient of variation` of per-second WPM samples.
- **Modes**: the island only talks to the `TestMode` contract (`initialSentences`, `shouldAppend`, `isFinished`, `effectiveElapsedMs`). `time` appends sentences until time runs out; `quote` ends when the last character is typed; `count` shows 1, 3, 5 or 10 sentences at once (`COUNT_OPTIONS`; the number is `TestSettings.sentenceCount`, default 3, read by `initialSentences(next, settings)`) and ends when the last character is typed, scored on the real elapsed time like `quote`. `relaxed` and `custom` are described in the next points. `TestMode` has three optional markers, `scored`, `showsClock` and `hasRecords` (absent = true); `relaxed` sets the first two to false, `custom` sets `hasRecords` to false. `SCORED_MODE_IDS` (`test-modes/index.ts`) lists the modes that are scored, and the history only accepts those (`ScoredModeId` in `lib/types.ts`), so a relaxed session can never reach it, even through an imported file. `RECORD_MODE_IDS` lists the scored modes that also keep personal bests (`RecordModeId`): the record keys (`isBucketKey`, `parseBucketKey`, `BucketInfo`) only know those, so custom text has no bucket and no record, even through an imported file. `getModeLabel` (`test-modes/label.ts`) builds the label shown in the history and statistics ("Time 30s", "Count 5", "Sentence").
- **Relaxed mode** (`features/relaxed`): the "Relaxed" chip (`ModeId` `relaxed`) lets the user read facts while typing, with no clock, WPM, accuracy or chart. Sentences come **one at a time** from the same filtered queue as the other modes (category and difficulty apply; the weak-key practice button and the duration and count options are hidden, and `focus` is ignored, because relaxed mode records no key statistics). `TypingTest` hands the session to `RelaxedSession.svelte` (remounted with `{#key}` for each new session: a mode, filter or sentence-language change, "Restart" or "New session") and only supplies the first sentence, the queue (`next`), the favorites, and two callbacks. The component uses `TypingArea` and the engine as they are, **without stop-on-error**: a mistake stays marked (red, underlined) but never blocks, and the sentence is done when its last character is typed. Then the area is disabled and an **inline card** appears below it (`SentenceCard`: text, explanation, source, star, "Report a wrong fact" link) with **Continue** (focused, so Enter continues; Enter also continues when nothing else has focus) and **Finish**. While typing, **Finish** is at the top right, and Esc starts the current sentence over. **Finish** shows the summary: the number of sentences typed and the list of those sentences (each once, with explanation, source and star) and a **New session** button; finishing in the middle of a sentence does not count that sentence. `relaxed-session.ts` is the pure state machine (`startSession`, `completeSentence`, `advance`, `finishSession`, `countCompleted`, `getLearnedSentences`; `relaxed-session.test.ts`). **What is stored:** every finished sentence goes into `typing:seen:v1:<contentLang>`; the session counts **once** for the streak and the daily goal, when its first sentence is finished (`recordActivity`; `handleRelaxedDone` in `TypingTest`; saves run one after another). **Nothing** goes to the history, the personal bests or `key-stats`, and there is no share button (nothing to share). No new storage key, so export, import and the privacy page are unchanged. The typing sound (if on) plays for relaxed typing too.
- **Custom text** (`features/custom-text`): the "Own text" chip (`ModeId` `custom`) lets the user type a text of their own. Choosing the chip opens an **editor** (`CustomTextInput.svelte`) instead of the typing area: a `textarea` (at most 1,000 characters, 16 px so iOS does not zoom, with a character counter), a **preview** of what will be typed, a note "N characters were changed or removed" when the text had to be made typeable, an error when nothing typeable is left or the changed text is over the limit, a **Start typing** button, and the **last 5 texts** ("Type this text" starts one right away, "Remove this text" deletes it). The category and difficulty selects and the weak-key practice button are hidden (no corpus is used). After Start, `TypingTest` builds the target from the text (`customTarget`; `customMode.initialSentences` returns nothing) and runs the normal flow with `TypingArea` and the engine (Sentence-mode rules: ends when the last character is typed, scored on the real elapsed time; stop-on-error follows the setting). "Restart", Esc and "Try again" repeat the **same text**; **Change text** (next to Restart, and on the result) goes back to the editor, and clicking the chip again does too. **Normalization** (`normalize.ts`, pure and tested): curly quotes and dashes become ASCII (`“ ”` to `"`, `‘ ’` to `'`, en/em dashes to `-`, `…` to `...`); all whitespace (new lines, tabs, no-break spaces) becomes single spaces and the ends are trimmed; control, zero-width and soft-hyphen characters are dropped; other characters are replaced by their closest typeable form (accents are dropped by Unicode decomposition, `ß` becomes `ss`, `×` becomes `x`, a few symbols have a table) or dropped when they have none (emoji, other scripts). `changedChars` counts the characters replaced or dropped (whitespace changes are not counted). Empty text (also after the changes) is rejected (`empty`), as is a changed text over 1,000 characters (`too-long`; an ellipsis grows to three characters). The text does **not** go through `content-rules` and never becomes part of the corpus. **What is stored:** the last 5 texts in `typing:custom-texts:v1` (`{ id, text, savedAt }[]`, newest first; `custom-texts.ts`: `parseCustomTexts` is tolerant and drops texts that are not exactly what `normalizeCustomText` produces, `saveCustomText` moves a text that is already saved to the top instead of storing it twice, `removeCustomText`, `mergeCustomTexts`); a text is saved when it is started. The texts never leave the browser. The result enters the **history** with `mode: 'custom'`, `category` and `difficulty` `all`, and neither `sentenceIds` nor `categoryChars`; it is **never a personal best** (`recordResult` only writes the history; the WPM of different texts is not comparable) and there is no record banner. The result panel hides "What you just typed" (no explanation or source) and the share image has no fact (the user's text is never put on it). It counts for the **streak** and the daily goal and feeds the **key statistics** (of the sentence language chosen at that moment: a custom text has no language of its own), but not `seen`. The statistics page lists custom tests as one more WPM trend ("Own text"), has no record for it, and counts them in the total number of tests; their typing time is not in the total time (the history keeps no `categoryChars` for them to derive it from). The `customTexts` kind is in `data-schema.ts` (export, strict validator, merge: union by text, the later save wins, at most 5), `privacy.data.customTexts` and `DATA_KEY_LABELS`.
- **Persistence**: history (last 200 tests) and personal bests are stored through `StorageAdapter` under the keys `typing:history:v1` and `typing:personal-bests:v1`. **Content language** (`ContentLang` in `i18n/config.ts`) is the language of the sentences being typed and is separate from the interface language (the `/id/` or `/en/` URL). Every history entry stores `contentLang`; the personal-best bucket key is `<contentLang>:<mode>:<option>`, where the option is the duration in seconds (`time`), the sentence count (`count`, e.g. `en:count:5`, stored in the optional `sentenceCount` field of a history entry) or `na` (`quote`), so every count has its own record and statistics bucket (`getBucketOption` in `history.ts`); `seen` and `key-stats` have one key per content language (see below). The user chooses it with the switch on the home page; it is saved as `contentLang` in `typing:settings:v1` (`null` = never chosen, follow the interface language), and changing it loads the other language's sentences without changing the URL (so canonical, `hreflang` and the sitemap are unaffected). The target text carries `lang="<contentLang>"`. Entries without `contentLang` (saved before v20, when the field was `lang`) are dropped on load, not migrated.
- **Keyboard shortcuts** (`features/shortcuts/shortcuts.ts`, listeners in `TypingTest.svelte` and `RelaxedSession.svelte`): only the non-character keys **Esc** and **Enter**. **Tab is never taken over** (a keyboard trap, WCAG 2.1.2) and there are no single-character shortcuts (WCAG 2.1.4), so no setting to switch them off is needed. While typing, Esc restarts the test (unchanged; in relaxed mode it restarts the current sentence). **On a result screen**, Esc and Enter do what **Try again** does (`startNewTest()`; for custom text that repeats the same text, because `customTarget` is kept); on the **relaxed session summary**, Enter does what **New session** does; Enter on a relaxed card still means **Continue**. The rules are pure and unit tested (`shortcuts.test.ts`): `shouldHandleResultEnter` and `shouldHandleResultEscape` ignore a modifier (Ctrl, Meta, Alt, Shift), key repeat, an IME composition, an event another handler already used (`defaultPrevented`) and an open `<dialog>`. **Enter** is also ignored when the focus is on an interactive element (`isInteractiveTarget`: `a`, `button`, `input`, `textarea`, `select`, `summary`, `[role=button]`, editable content), so Enter on the star, a source link, a report link or Share keeps its own action, and during the first **600 ms** after the result appears (`RESULT_SHORTCUT_DELAY_MS`), so the habitual Enter at the end of typing does not close the result at once. **Esc** has no delay, and is ignored only in form fields and editable content (where the browser or the user uses it). `readShortcutEvent` reads these facts from a real `KeyboardEvent`. The `keydown` listener is on `document`, added by an `$effect` only while a result is shown and removed when leaving that state. **Tab order:** the **Restart** button now follows the typing area in the DOM (it was above it), so Tab from the field lands on Restart and then Enter works, with no positive `tabindex`. **Visible hint:** a `caption` line next to Restart (`<kbd>Esc</kbd>: restart`) and one under the result buttons (`<kbd>Enter</kbd>: try again`; dictionary keys `test.shortcutRestart` and `results.shortcutRetry`). The `.shortcut-hint` class (`global.css`) shows them only for `(hover: hover) and (pointer: fine)` and hides them on touch screens; the on-screen buttons stay the main way. Tests: `tests/e2e/shortcuts.spec.ts`.
- **Report a wrong fact** (`lib/report.ts`, `.github/ISSUE_TEMPLATE/fact-report.yml`): under each sentence in "What you just typed" there is a "Report a wrong fact" link. It is a plain link (no request from this site) that opens `<PUBLIC_REPO_URL>/issues/new?template=fact-report.yml&title=[Fact] <id>&sentence_id=<id>` in a new tab (`rel="noopener noreferrer"`), so GitHub shows the form with the sentence id already filled in. `buildFactReportUrl(repoUrl, id)` is pure and tested; it returns `undefined` (link hidden) when `PUBLIC_REPO_URL` is empty or the id is not made of lowercase letters, digits and hyphens. The form has the fields `sentence_id`, `what-is-wrong`, `correct-information` and `source-url`, and applies the label `fact-report` (the label must exist in the repository, see `MAINTAINING.md` 1.5, or GitHub drops it silently). `PUBLIC_REPO_URL` is read in `index.astro` and passed as the `repoUrl` prop through `TypingTest` to `ResultsPanel`. If you rename the file or the `sentence_id` field, change `FACT_REPORT_TEMPLATE` / `SENTENCE_ID_FIELD` in `lib/report.ts` too (`report.test.ts` checks both against the template). The collection page and the relaxed-mode card reuse it through `SentenceCard`.
- **Favorites and collection** (`features/favorites`, `pages/[lang]/collection.astro`): under each sentence in "What you just typed" there is a star toggle ("Save to collection", `aria-pressed`; the filled and outlined stars differ, so the state is not only a color). `typing:favorites:v1:<contentLang>` (one key per sentence language, like `seen` and `key-stats`, so the collection follows the sentence language; the specification's single `typing:favorites:v1` was split the same way as the other per-language data) holds `{ id, savedAt }[]`, **newest first**, at most 500 per language (the oldest is dropped when the list is full; an empty list removes the key). `favorites.ts`: `parseFavorites` (tolerant: invalid entries dropped, one entry per id with the latest time, sorted, trimmed), `mergeFavorites` (used by data import), and the storage functions `loadFavorites`, `toggleFavorite`, `removeFavorite` and `pruneFavorites(storage, contentLang, existingIds)`. `TypingTest` reads the collection of the current sentence language after the settings load (and again when the language is switched) and passes `favoriteIds` and `onToggleFavorite` to `ResultsPanel`, which stays presentational. The page `/[lang]/collection/` (island `CollectionPage.svelte`, linked in the main navigation) loads `/data/<contentLang>/sentences.json`, **prunes** saved ids that are no longer in the corpus (a sentence removed from the content files; skipped when the corpus came back empty), and lists the rest with the text, explanation, source, a "Report a wrong fact" link (same `buildFactReportUrl` and `repoUrl` as the results), a "Remove from collection" button and a category filter. It uses the same `contentLang` setting as the home page and the same language switch (`ContentLangSwitch`), so changing it there changes the home page too. `SentenceCard.svelte` renders one sentence for both the results list and the collection (the buttons next to the report link come in through the `actions` snippet; the report link is hidden without `PUBLIC_REPO_URL`). After a removal the focus moves to the "Saved sentences: N" line and a polite live region announces it. The `favorites` kind is also in `data-schema.ts` (export, import with a strict validator and a merge rule: union by id, the later save time wins), `privacy.data.favorites` and `DATA_KEY_LABELS`. **Undo:** "Remove from collection" still removes at once, then a `role="status"` row appears next to the count line with the message and an **Undo** button. There is **no timer and no confirmation dialog**: the row stays until the next removal (the earlier one becomes permanent, so only the last removal can be undone), until Undo is pressed, until the sentence language is changed, or until the page is left. `restoreFavorite(storage, contentLang, entry)` puts the entry back with its **original `savedAt`** (it returns to its old place in the newest-first list), adds no second copy when the id is saved again meanwhile, and keeps the limit of 500 (the oldest entry is the one dropped). The focus after a removal stays on the count line (Tab reaches Undo next); after Undo it goes to the Remove button of the restored card, or to the count line when the category filter hides that card; when the removal emptied the list there is no count line, so the focus goes to Undo itself. The star in the results panel is unchanged (tap again to undo).
- **Statistics page** (`features/stats`, `pages/[lang]/stats.astro`): `/[lang]/stats/` (island `StatsPage.svelte`, linked in the main navigation between Home and Collection) shows, for **one sentence language** (the same `contentLang` setting and `ContentLangSwitch` as the home page and the collection; the interface language does not matter): (1) totals: tests finished, typing time, sentences learned; (2) a WPM trend of the last 30 tests (`TREND_LIMIT`) of the chosen mode (a `<select>` of the modes that have tests; it starts with the mode of the newest test) with the latest, average and best WPM and an inline SVG chart (`TrendChart.svelte`: no chart library; the axis labels are HTML so they stay at 14 px; the SVG has a text alternative with the numbers); (3) accuracy per category; (4) sentence coverage per category (sentences typed to the end, from `seen`, against the corpus loaded from `/data/<contentLang>/sentences.json`; ids that are not in the corpus any more are ignored); (5) personal bests of that language. The page stores nothing and adds no storage kind, so export, import and the privacy page are unchanged. `stats.ts` holds all the logic as pure functions (`filterByContentLang`, `computeTotals`, `estimateTypingSeconds`, `splitDuration`, `listBuckets`, `getTrend`, `summarizeTrend`, `getTrendMax`, `computeCategoryAccuracy`, `computeCoverage`, `listPersonalBests`; `stats.test.ts`). Three things to know. **The totals come from the history, which keeps at most 200 tests** (`MAX_HISTORY_ENTRIES`), so "tests finished" and "typing time" stop growing at that point; the page says so under the totals. **Typing time is derived**, because a history entry stores no elapsed time: a test with a fixed duration (time mode) lasted that long; any other test lasted `typed characters / 5 / raw WPM` minutes (the typed characters are the sum of `categoryChars`; entries saved before typing-v13 have none and count as 0). **Accuracy per category is an estimate for mixed tests**: an entry stores one accuracy and the characters per category, not the errors per category, so the accuracy of a test is credited to each category in proportion to its characters (the character-weighted mean over the tests that touched it; exact for a test of a single category). The weak-keys section is described next.
- **Streak and daily goal** (`features/streak`): `typing:streak:v1` (one value for the whole app, not per sentence language) holds `{ lastDay, current, best, todayCount }`: `lastDay` is the local calendar day (`YYYY-MM-DD`, the device time zone) of the latest finished test, `current` the days in a row up to it, `best` the longest streak, `todayCount` the tests finished on `lastDay`. `streak.ts` is pure and takes the day or date as an argument, so tests inject dates: `toDayKey`, `daysBetween` (UTC day numbers, so daylight saving never shifts a day), `parseStreak` (strict: returns `null` for anything inconsistent, e.g. `best < current` or a day that does not exist), `advanceStreak(streak, today)` (same day: only `todayCount` grows; next day: `current + 1`; first test or a skipped day: starts at 1 and `best` is kept; a clock that went backwards is treated as the same day), `getStreakView(streak, today)` (what to show: the streak stays alive until a whole day passes without a test, `todayCount` is 0 on a new day), `mergeStreaks` (data import: the later day wins, `best` is the higher), `getGoalProgress`, and the storage functions `loadStreak` (a missing or damaged value counts as no streak) and `recordActivity(storage, now)`. `TypingTest` calls `recordActivity` at the end of `persistResult` for every finished test (every scored mode, custom text included; relaxed mode calls it once per session, when its first sentence is finished) and shows `StreakBadge.svelte` above the controls: a small flame icon with "N-day streak" and, when `dailyGoal` is not 0, "N of G tests today" with a bar and a "Goal reached" label (numbers carry the meaning, the bar is decorative). The daily goal (off, 1, 3 or 5 tests) is a `Settings` field with a section on the settings page; it only affects the progress display, never the streak. The badge is hidden when there is neither a streak nor a goal. The `streak` kind is in `data-schema.ts` (export, strict validator, merge), `privacy.data.streak` and `DATA_KEY_LABELS`.
- **Weak keys** (`features/stats/weak-keys.ts`, section in `StatsPage.svelte`): the statistics page shows, for the chosen sentence language, a QWERTY **heat map** and a list of the **weakest keys**, both read from `typing:key-stats:v1:<contentLang>` (see \"Captured learning data\"; nothing new is stored, so export, import and the privacy page are unchanged). A key is judged only after `MIN_KEY_ATTEMPTS` = 30 attempts. Heat map: three rows drawn in the **keyboard layout of the sentence language** (`KEYBOARD_ROWS` in `weak-keys.ts`, read through `getKeyboardRows(contentLang)`: AZERTY for `fr`, QWERTZ for `de`, QWERTY for every other language; a row is as wide as its number of keys, so the second AZERTY row has ten cells and the third six), one cell per letter with its letter and its error rate as a whole percentage; accented letters have **no cell** (the map shows plain letters only) but are counted in `key-stats` and appear in the weak-key list and in weak-key practice; the fill has three levels from the error rate (`HEAT_THRESHOLDS`: 2%, 5%, 10%; levels 2 and 3 also get a red border), so the state never depends on color alone. A key with fewer than 30 attempts (or never typed) is drawn with a dashed border and a dash instead of a number. Weak keys: at least 30 attempts and at least one mistake, highest error rate first (ties: more errors, more attempts, then the key), the top `WEAK_KEYS_LIMIT` = 5, each with its rate and \"N errors in M attempts\". **The space bar is not listed** (it is in every sentence, so it says nothing about which letters to practice); digits, punctuation and letters of other languages are. The section shows when the language has tests or any key count; an empty state explains what a key needs to be listed. All logic is pure (`buildHeatmap`, `getKeyboardRows`, `listWeakKeys`, `getErrorRate`, `getHeatLevel`, `hasKeyData`, `formatKey`; `weak-keys.test.ts`). The weak-key practice option reuses the same definition of a weak key.
- **Weak-key practice** (`sentence-picker/weak-key-picker.ts`, a toggle in `TypingTest.svelte`): the **"Practice weak keys"** button on the home page sets `TestSettings.focus` (`'none' | 'weak-keys'`). It is an option of the current test like the category filter: it is **not saved** in `typing:settings:v1` and starts off on every page load; the Fact of the day button turns it off (that test uses one given sentence). When a test starts with practice on, `TypingTest` waits for the previous result to be saved, reads `typing:key-stats:v1:<contentLang>` of the language of the sentences in use, and takes the weak keys with `listWeakKeys` from `stats/weak-keys.ts` (the same definition as the statistics page: at least 30 attempts and one mistake, the 5 worst, no space bar). `pickWeakKeySentences(pool, weakKeys)` then works on the pool left by the category and difficulty filters: `scoreSentence` is the share of a sentence's characters that are weak keys (compared lowercased, like `key-stats`); sentences are ranked best first (ties by id), the top `PRACTICE_POOL_SHARE` = 30% are kept (at least `MIN_PRACTICE_POOL` = 5), and sentences without a weak key are dropped unless that would leave fewer than 5 (then the pool is filled up with the next best ones, so a rare key never makes the same one or two sentences repeat). It writes no new text and does not shuffle: `createSentenceQueue` shuffles the pool as for any test, so every mode (time, sentence, count) works unchanged. With no weak key yet the pool is the normal one and a note says so; with weak keys the note lists them (`ui.test.focusActive` / `focusNoData`). A practice test is saved like any other (history, personal best, `seen`, key stats, streak); its sentences are harder on purpose, so its WPM is usually lower and it rarely sets a record. Tests: `weak-key-picker.test.ts` (unit) and `tests/e2e/weak-keys-practice.spec.ts`.
- **Captured learning data** (read by the statistics page and the collection; the weak-key features read `key-stats`: the statistics page and the weak-key practice option). Each history entry also stores `sentenceIds` (sentences the user started typing, in order) and `categoryChars` (typed characters per category, categories with none omitted); both are optional, so entries saved earlier still load. `features/results/learned.ts` holds the offset math (`getTypedSentences`, `getCompletedSentences`, `getCategoryChars`). `typing:seen:v1:<contentLang>` (e.g. `typing:seen:v1:id`; `features/seen`, `loadSeen(storage, contentLang)` and `markSeen(storage, contentLang, ids)`) is the list of ids of sentences typed to the last character at least once (errors do not matter). `typing:key-stats:v1:<contentLang>` (`typing-engine/key-stats.ts`, `loadKeyStats(storage, contentLang)` and `recordKeyStats(storage, contentLang, session)`) is `{ [char]: { attempts, errors } }` per lowercased target character, spaces and punctuation included: every newly typed character is an attempt, and an error if it differs from the target, so erased mistakes still count. The counts of a test are saved when it finishes; when a key passes 500 attempts, its attempts and errors are halved. Relaxed mode records only `seen` (and the streak); custom text records the key statistics and the streak, but neither `seen` nor `categoryChars`.
- **Storage contract** (`lib/storage`): `get`, `set`, `remove`, `keys(prefix?)` and `clear(prefix?)`. Keys are relative to the adapter: the localStorage adapter writes `history:v1` as `typing:history:v1`, and `keys()` returns `history:v1` again. `clear()` with no argument removes everything in the adapter's namespace (other apps' keys are never touched). The localStorage adapter falls back to an in-memory map when localStorage is unavailable or full; `keys`, `remove` and `clear` cover both places.
- **Fact of the day** (`features/daily-fact`): the home page shows one sentence per local day with its explanation, source and a "Type this sentence" button (`DailyFact.svelte`, rendered by `TypingTest` between the test area and the history list). The choice is deterministic, not random: `index = hash(YYYY-MM-DD + contentLang) mod number of sentences` (`daily-fact.ts`, pure: 32-bit FNV-1a hash; the day is an argument, made by `toDayKey` from the streak module, so tests inject dates). The corpus is sorted by id before indexing, so everyone sees the same sentence on the same day and the site stays static. It uses the whole sentence file of the active sentence language (the category and difficulty filters do not apply), follows the sentence language switch, and counts the corpus size, so adding or removing a sentence changes the pick. The button sets Sentence mode, resets the filters to "all" and starts a test with that sentence (`startWithSentence`; the same code path serves the `initialSentenceId` prop of `TypingTest`, which opens the page with a given sentence); the result is saved like any other test (history, personal best, seen, streak). No stored data of its own.
- **Settings** (`features/settings`): `settings.ts` holds the `Settings` type, `DEFAULT_SETTINGS`, and `loadSettings` / `saveSettings` for the key `typing:settings:v1`. Reading is tolerant: unknown keys are dropped and each missing or invalid field falls back to its own default, so old, hand-edited or newer data never breaks the app. Fields: `theme` (`system` | `light` | `dark`), `fontSize` (`sm` | `md` | `lg`), `dailyGoal` (0 = off, 1, 3, 5), `sound`, `volume` (0 to 1), `stopOnError`, `caretStyle` (`line` | `block` | `underline`), `contentLang` (a lowercase language code or `null`; whether the folder still exists is checked by the page, which falls back to the starting language). `settings.svelte.ts` exports `settingsStore`, a Svelte 5 rune store shared by all islands: call `await settingsStore.init()` after mount, read `settingsStore.current` inside `$derived` or `$effect`, change values with `settingsStore.update({ ... })` (saves are queued, so the last update wins). Nothing reads storage at import time (safe for server rendering). The settings page (`SettingsPanel.svelte`, route `/<lang>/settings/`) changes `theme`, `fontSize`, `caretStyle`, `stopOnError`, `sound`, `volume` and `contentLang`; the home page switch (`ContentLangSwitch.svelte`, shared with the settings page) changes `contentLang`. `dailyGoal` is chosen on the settings page too (see Streak and daily goal). The settings page also changes `caretStyle`, `stopOnError`, `sound` and `volume` (see Advanced options).
- **Advanced options** (`features/sound`, the settings page, `typing-engine`): three independent settings, all stored in `typing:settings:v1` (no new key, so export, import and the privacy page keep working). **Caret style** (`line` default, `block`, `underline`): the CSS of the caret now lives in `styles/global.css` (`.caret` inside `.typing-text[data-caret-style]`), shared by the typing area and the preview on the settings page, which uses the chosen text size. **Stop on error**: `TypingTest` reads the setting when a test *starts* (`stopOnError` state), so a test never changes rules midway; a note under the hint tells the user to delete the wrong character. Such a test is saved with `stopOnError: true` in its history entry and has **its own personal-best bucket**: the key gets a fourth segment, `<contentLang>:<mode>:<option>:soe` (for example `en:time:30:soe`; tests without the option keep the three-segment key, so existing data is unchanged). `getBucketKey` / `parseBucketKey` / `isBucketKey` in `history.ts` handle it; the statistics page lists it as a separate bucket after the same option without it, and `getModeLabel` adds the tag "Stop on error". **Typing sound** (`features/sound/typing-sound.ts`): one short click per accepted character, made with WebAudio (a 30 ms triangle wave falling from 2000 to 500 Hz; no audio files). `createTypingSound()` creates its `AudioContext` lazily on the first click that is played (browsers need a user gesture), is a silent no-op when WebAudio is missing or the volume is 0, and swallows audio errors. The volume (0 to 1) maps to a gain of at most 0.25, so the click stays quiet; the settings page has a slider (saved when released) and a "Try the sound" button. Deleting, or typing that stop-on-error refuses, makes no sound. Off by default.
- **Share the result as an image** (`features/results/share-image.ts`, `share-result.ts`): the result panel has a **Share** button next to "Try again". The image is drawn in the browser on a `<canvas>` of 1200x630 (`renderShareImage`): site name, the mode with its option (`getModeLabel`, so a stop-on-error test carries its tag), WPM, accuracy, and one short fact, which is the text of the first sentence typed to the last character (otherwise the first one started; `pickShareFact`). No server and no personal data are involved, nothing is stored, and the image is not sent anywhere by this site. It uses a **fixed light palette** (the light-mode design palette, `SHARE_PALETTE`), not the theme of the page, so it looks the same wherever it is shared; the figures are `accent` on `surface` (5.3:1) and the labels `text-muted` (6.7:1). The fonts are the ones of the page (Bricolage Grotesque and Inter; the canvas asks the browser to load them through `document.fonts.load` and falls back to `sans-serif`). The fact is wrapped to at most 3 lines (`wrapText`, pure and tested with a fake measure function) and ends with an ellipsis if it is longer. The image is **drawn as soon as the result appears**, not on the click, because browsers (iOS Safari especially) refuse `navigator.share` when too much time passes after the tap; the click only shares the ready blob. `shareOrDownload` (pure apart from the DOM download helper, tested with a fake navigator) calls `navigator.share({ files })` when `navigator.canShare({ files })` says the browser can share files, otherwise downloads `typing-result-<wpm>wpm.png` through a temporary link; a dismissed share sheet (`AbortError`) is silent, and any other share error falls back to the download, so the user always gets the image. After a download a polite status line says that the PNG was saved. Sharing requires a secure context (HTTPS, or localhost). Tests: `share-image.test.ts`, `share-result.test.ts` and `tests/e2e/share-image.spec.ts` (download is a real 1200x630 PNG; a fake Web Share API receives a PNG file; dismissing is silent; the Indonesian page). What the e2e tests cannot judge is how the picture looks: open it once. **Button feedback:** the drawing has a status (`ShareImageStatus`: `preparing`, `ready`, `failed`; pure `getShareButtonState` in `share-button-state.ts`, unit tested). While `preparing` the button is **`aria-disabled="true"`** (it stays focusable, unlike a native `disabled`), reads "Preparing image..." (`results.shareBusy`) and ignores clicks. When `ready` the click shares the finished blob, with no `await` before `navigator.share`. When `failed` the status line shows `results.shareFailed` and the button is active again: that click **draws the image again** (it does not share in the same click, which iOS would refuse) and the next click, once the image is ready, shares it. A drawing that finishes late for an older request is ignored (token). The `.btn[aria-disabled='true']` style in `global.css` matches `:disabled` (dashed border, muted text) and has no hover effect.
- **Theme** (`features/settings/theme.ts`, `styles/tokens.css`): the colors follow the system through `prefers-color-scheme`; `data-theme="light"` or `"dark"` on `<html>` forces a mode, and no attribute means `system`. `BaseLayout` puts `THEME_INIT_SCRIPT` inline at the top of `<head>`: a few lines of plain JavaScript that read `typing:settings:v1` and set `data-theme` before the first paint, so a saved choice never flashes the other theme. It does nothing when storage is blocked or the data is invalid. `SettingsPanel` calls `applyTheme` when the saved settings have loaded and on every change (before the load it must not touch `<html>`, or it would undo the script). The script is a constant with no runtime data, so `BaseLayout` can hash it for the Content Security Policy (see "Deploy"). **Navigation and footer** (`MainNav.astro`, `BaseLayout.astro`): the header has the site name, the language switcher and a main navigation with one entry per page that exists (home, settings); the footer repeats the settings link, links the repository when `PUBLIC_REPO_URL` is set, and states the sentence license (CC BY-SA 4.0, linked to `LICENSE-CONTENT` in the repository when `PUBLIC_REPO_URL` is set, otherwise to the license text). The 404 page hides both.
- **Data tools and privacy** (`features/data-tools`, `pages/[lang]/privacy.astro`): **`data-schema.ts`** is the one list of what the app stores in the browser. `DATA_KINDS` (`history`, `personalBests`, `settings`, `seen`, `keyStats`, `favorites`) with `DATA_KEY_LABELS` (the storage key of each kind, `<lang>` standing for a sentence language code) and `getDataKind(key)` (which kind a key belongs to, or `null`). For each kind there is a strict validator (`validateValue`: a wrong part makes the whole value invalid, unlike the tolerant runtime readers, which drop bad entries) and a merge rule (`mergeValue`): history = union by id, newest first, trimmed to 200; personal bests = the higher WPM per bucket; settings = the current ones win (the imported ones are used only when none are stored); seen = union; key stats = counts added, then the usual decay; favorites = union by id, the later save time wins, newest first, trimmed to 500. **`data-transfer.ts`**: `buildExport` writes `{ app: "typing", version: 1, exportedAt, data: { <key>: <value> } }` (keys are relative to the adapter, e.g. `history:v1`, as everywhere else in the code; only values the import would accept are written, so export then import always works), `exportFileName` gives `typing-data-YYYY-MM-DD.json` (local date), `parseImport(text)` checks size (1 MB), JSON, shape, `app`, `version` (only 1), that the file has data, and every key with its own validator (an unknown key or one damaged value rejects the **whole file**; the result names the error code and the key, and nothing is written), `applyImport(storage, data, 'merge' | 'overwrite')` writes the checked data and, if a write fails halfway, puts the previous data back and rethrows (all or nothing), and `clearAllData` calls `storage.clear()`. **`DataTools.svelte`** (an island on the settings page, rendered after mount): export downloads the file through a Blob link; import opens the file picker, shows "valid file" with the number of tests, lets the user choose "merge" (default) or "overwrite" and press "Import" (overwrite asks again in a dialog); "delete all data" asks in a dialog. The confirmation dialog is a native `<dialog>` (`showModal`: focus trap and Escape for free). After an import or a delete the page calls `settingsStore.reload()` so the theme and the other settings shown are the stored ones (reload reads storage again and never saves). Messages are in the `dataTools` dictionary section (rejection reasons keyed by `ImportErrorCode`). **Privacy page**: all text is in the `privacy` dictionary section; the list of stored data is rendered from `DATA_KINDS`, and the dictionary has one text per kind (`privacy.data`), so a new kind of stored data makes TypeScript ask for its privacy text in both languages. **A feature that stores something new must add its kind in `data-schema.ts`** (key pattern in `getDataKind`, validator and merge rule in the two switches, entry in `DATA_KEY_LABELS`) and its text in `privacy.data`; the export, import and privacy page then include it. The privacy text describes the real behavior (no cookies, no accounts, nothing leaves the browser, analytics only when a token is configured) and should be reviewed by you before release. `loadPersonalBests` is tolerant (`parsePersonalBests` keeps only entries with a valid bucket key and a non-negative number).

- **Design tokens and fonts** (`src/styles`, `astro.config.mjs`): `tokens.css` is the only source for colors and `astro.config.mjs` for fonts; sizes, contrast of the typing text and breakpoints follow common best practice. `tokens.css` holds the raw color variables (`--background`, `--surface`, `--text`, `--text-muted`, `--accent`, `--error`, `--border`, `--primary`, `--on-primary`, plus `--typing-pending` and `--typing-correct` for the typing area). Fonts are self-hosted through Astro's Fonts API with the `local` provider and the variable files of the `@fontsource-variable/*` packages (latin subset for Bricolage Grotesque and Inter, which only show text we write in the interface languages; Lora has more subsets, see below): Bricolage Grotesque (`font-heading`, h1 to h3), Inter (`font-ui`, also the default `font-sans`) and Lora (`font-typing`, typing area only). `BaseLayout.astro` outputs the `@font-face` rules and preload links with the `<Font />` component; Lora is preloaded only when a page sets `preloadTypingFont`, and then only its latin file. **Lora subsets** (`src/config/font-subsets.ts`): latin, latin-ext, vietnamese, cyrillic and cyrillic-ext are five `@font-face` rules of the same family, each with the `unicode-range` of its Fontsource file, so the browser downloads a file only when the page contains a character of that range (an ASCII-only page loads just the latin file, about 38 KB). `BaseLayout` renders the preload link itself for the first subset (`<Font preload>` would preload all five). `font-subsets.test.ts` compares the list with the installed package, so an upgrade of `@fontsource-variable/lora` that changes a file or range fails the tests until the list is updated. All targets are at least 44x44 px, the `.field` font is 16 px so iOS Safari does not zoom, and hover styles apply only where hover exists. The shell (`BaseLayout`, header, `LanguageSwitcher`) and the controls in `TypingTest.svelte` use tokens only. `.card` is the result card (surface, 12 px radius, `--card-shadow`: a soft shadow in light mode, a 1 px border in dark mode). A page passes its `path` inside the language (`''` for home, `'settings'`, ...) so canonical and `hreflang` point to the same page in each language. `@astrojs/sitemap` is added only when `SITE_URL` is set (it needs `site`) and writes `sitemap-index.xml` and `sitemap-0.xml` with `hreflang` alternates (`i18n` option: `id-ID`, `en-US`). `robots.txt` is generated from `src/pages/robots.txt.ts` (allow all; the `Sitemap:` line appears only with `SITE_URL`). `404.astro` is one bilingual page (each block has its own `lang`; a static host serves one 404 file for every unknown URL) with `noindex`, no canonical and no structured data; Cloudflare Pages and Netlify serve `404.html` automatically. The Open Graph images are in `public/og/` (see "Brand assets").

The script fails if a text color on the Open Graph image drops below 4.5:1, if text overflows the card or overlaps another block, or if an Open Graph image is 300 KB or larger. The generated files are committed; run the script again only when the palette, logo, site names or taglines change. `src/lib/brand-assets.test.ts` checks that the files exist with the right dimensions. To use your own artwork, replace the files at the same paths (the layout and the web manifest refer to these paths). If Playwright's browser is not installed, run `pnpm exec playwright install chromium` first, or set `CHROMIUM_PATH` to a Chromium binary. `BaseLayout` links `favicon.svg` and `apple-touch-icon.png`; the 192, 512 and maskable icons are used by the PWA manifest.

- **Installable app and offline use** (`src/config/pwa.ts`, `src/lib/manifest.ts`, `src/lib/pwa-build.ts`, `src/lib/pwa-integration.ts`, `src/pwa/sw-template.js`, `src/features/pwa/`): written by hand, **no PWA dependency** (a plugin was not needed for a site this small, and `@vite-pwa/astro` support for Astro 7 could not be confirmed). Each interface language has its own manifest (`/id/manifest.webmanifest`, `/en/manifest.webmanifest`, generated from the dictionary) with `start_url` and `id` `/<lang>/`, `scope` `/`, `display: standalone`, the three icons of `public/icons/`, and `theme_color` / `background_color` `#ddf4ff` (the design `background`; the page also sets light and dark `theme-color` meta tags, `#ddf4ff` and `#0f1c26`). There is one manifest per language, so an app installed from `/en/` opens `/en/`. After `astro build`, the integration `pwa()` (last in `astro.config.mjs`) lists `dist/`, fills `src/pwa/sw-template.js` and writes `dist/sw.js` (build log: `sw.js written: N files and M data files, revision <hash>`). The worker **precaches** every page (both languages, settings, privacy, collection, stats), script, style, font and icon, and keeps `/data/<lang>/sentences.json` in a separate cache that is served at once and refreshed in the background (**stale-while-revalidate**). It does not store `og/` images, `robots.txt`, sitemaps, `404.html`, `_headers` or itself. Pages and assets come from the precache first; an address that is not stored goes to the network, and when that fails the home page of the same language is shown (`/en/never-stored/` offline shows `/en/`). **Updates:** the revision hash covers every stored file and the template, so any visible change gives a new `sw.js`. The new worker installs next to the old one and **waits** (no `skipWaiting`); `PwaUpdater.svelte` (in `BaseLayout`) shows the toast "A new version is available" with "Reload" and "Later", and only the tap on "Reload" sends `SKIP_WAITING`, activates the worker and reloads, so a running test is never interrupted. The first install shows no toast. The page also asks the browser to check for an update when the app returns to the foreground, at most once an hour. The worker is registered only in a production build (not in `pnpm dev`) and only when the browser supports it; failure to register is silent and the site works without it. `public/_headers` serves `/sw.js` with `Cache-Control: no-cache`. CSP: the worker needs nothing new (`worker-src` falls back to `default-src 'self'`; the manifest is covered by `manifest-src 'self'`). Browser-side logic (`register.ts`) and build-side logic (`pwa-build.ts`) are pure and unit tested; `tests/e2e/pwa.spec.ts` (8 tests) runs the production build with a real worker: manifests and icons, theme colors, `sw.js` content, a whole test finished **offline** (reload, then settings and stats in both languages), the fallback page, and the update toast (shown, never reloads by itself, reloads on request, "Later" hides it). All other e2e specs block service workers (`playwright.config.ts`), so cached answers cannot hide their `page.route` rules. **To test by hand:** `pnpm build && pnpm preview`, open the site once, then in DevTools > Application > Service Workers tick "Offline" and reload. **Toast position:** the e2e test showed that a toast fixed at the bottom covered the typing field at 390x844, so it is now fixed at the **top** (`top-0`, `env(safe-area-inset-top)`); the live region (`role="status"`) exists before the toast, nothing moves the focus, nothing shifts the layout, and both buttons use `.btn` (44x44 px minimum). `pwa.spec.ts` has a test for position, focus and target size (the update is simulated by registering `/sw.js?update-test`, as in the other two toast tests).
- **Content tools** (`scripts/`, logic in `src/lib/content-stats.ts` and `src/lib/source-check.ts`, both unit tested): the scripts run with plain Node (type stripping, Node 22.18 or newer; no extra dependency) and read `src/content/sentences/<lang>/<category>.json` directly, so every language folder that exists is covered. `pnpm content:stats` prints a table per language (and category, difficulty) and also shows the spread of the difficulty scores per language (min, median, max, next to the threshold in use), and warns when a category has fewer than 100 sentences, a difficulty share is more than 10 points away from 50/50 (checked only for categories with 10 or more sentences), or a sentence's label differs from its score. `--scores` first lists every sentence with its score and level, lowest score first, and marks a wrong label. It exits with 0 unless you add `--strict`. `pnpm content:check-sources` requests each unique source URL (HEAD, then GET to confirm a failure; 15 s timeout, 4 at a time, 2 retries for server errors, timeouts and network errors). **Broken** = 404, 410 or an unknown host (exit code 1); **uncertain** = 403, 429, other errors and timeouts (warning only, because many sites block automatic requests). Both accept `--dir <path>`; the link check also accepts `--report <file>` (Markdown). `.github/workflows/link-check.yml` runs the link check every Monday and on demand, adds the report to the job summary, and opens or updates one issue labelled `content` when links are broken (the label must exist; see `MAINTAINING.md`). The scripts import with explicit `.ts` extensions and avoid the `@/` alias, because Node does not resolve it.

## Extending

- **New category**: add it to `CATEGORIES` in `lib/taxonomy.ts`, then add its label to every dictionary in `i18n/ui/` (TypeScript will list the missing ones), then add `<lang>/<category>.json` files.
- **New sentence language**: add the folder `src/content/sentences/<code>/`; see "Adding a sentence language" below. A language that uses plain ASCII and the `en` length range and score threshold needs no code change (calibrate the threshold before launching it, see "Difficulty").
- **New interface language**: add it to `LANGUAGES` in `i18n/config.ts`, create `i18n/ui/<lang>.ts`, register it in `i18n/index.ts`. If it has no sentence folder, the test starts in the default sentence language.
- **New mode**: add its id to `ModeId` in `lib/types.ts`, implement `TestMode` in `features/test-modes/`, register it in `test-modes/index.ts`, and add its label to the dictionaries. A mode that produces no score sets `scored: false` and must also be excluded from `ScoredModeId` in `lib/types.ts` (as `relaxed` is), so the history and records never accept it. A scored mode whose results are not comparable sets `hasRecords: false` and is also excluded from `RecordModeId` (as `custom` is), so it enters the history but never the personal bests.
- **Accounts, leaderboard**: implement an API-backed `StorageAdapter` and return it from `getStorage()` in `lib/storage/index.ts`; features do not change.
- **Fonts / colors**: change a color only in `tokens.css` (both dark copies, then run `pnpm test:run`); a new font is another entry in `fonts` in `astro.config.mjs` plus a `--font-*` line in `global.css`.
- **New page**: pass `path` (and, when the page should not be indexed, `noindex`) to `BaseLayout`, so canonical and `hreflang` are correct; the sitemap picks up every built page by itself. Add the page to `items` in `components/MainNav.astro` and its label under `nav` in the dictionaries.
- **New kind of stored data**: add its kind in `features/data-tools/data-schema.ts` (see "Data tools and privacy" above) and its text under `privacy.data` in the dictionaries.
- **New setting with a control**: add the field to `Settings` (`settings.ts`, with its parser and tests), then a control and its labels (dictionary `settings` section) in `SettingsPanel.svelte`.
- **New public setting**: add a parser to `config/parse.ts` (with tests), read it in `config/site.ts` and add it to `.env.example` and the table below.

### Draft sentence languages

`src/config/languages.ts` holds `DRAFT_LANGUAGES` (now `es`, `pt-br`, `fr`, `de`). A **draft** language is built and validated like any other (content rules, `/data/<code>/sentences.json`) but is **not offered in the sentence language select of a production build**, so visitors never see a language with only a few sentences. In `pnpm dev` every language is listed. Launching a language = deleting its code from `DRAFT_LANGUAGES` (one line). The select is filtered by `listSelectableContentLangs(available, { dev, active })` (pure, tested), used by the home, collection, statistics and settings pages with `import.meta.env.DEV`; the full list stays what `resolveContentLang` accepts, so a draft that is saved in `contentLang` (for example set through `localStorage` in a test) still works, and a draft that is in use stays listed, so the select is never blank. The rules of the four languages (allowed letters, forbidden characters, length range, starting difficulty threshold) are in `LANGUAGE_RULES`, `TEXT_LENGTH` and `DIFFICULTY_THRESHOLDS`; **the thresholds and ranges are starting points, not measured** and must be calibrated with `pnpm content:stats --scores` before a language is launched. **Sample data:** only `es` has sentences so far, 5 per category (20 in all, 12 easy and 8 hard) with accents and Spanish Wikipedia sources; they exist to exercise the pipeline and are **not verified** (facts and URLs are the owner's task before launch). `src/lib/es-sample-data.test.ts` checks them with the build rules, `pnpm content:stats` marks every draft language, and the language names (`Intl.DisplayNames`, for example `Spanyol` / `Spanish`, `Portugis (Brasil)` / `Brazilian Portuguese`) are tested. Typing accented letters (NFC, dead keys) is handled by the engine (see "Engine") and the heat map follows the keyboard layout of the language (step 6 below). **Checklist before launching a draft language** (the same list, with the clicks, is in `MAINTAINING.md`, section 10): (1) about 20 sentences per category at least (the final target is 100), checked by someone who knows the language; (2) a source in that language where one exists, and every fact and URL verified (`pnpm content:check-sources`); (3) the difficulty threshold and the length range calibrated with `pnpm content:stats --scores` (step 4) and every label matching; (4) the accented sentences typed by hand with the real keyboard layout of the language, on a desktop and on a phone (step 8); (5) delete the code from `DRAFT_LANGUAGES`, then `pnpm check && pnpm test:run && pnpm build` and look at the select.

### Adding a sentence language

A sentence language is a folder; the interface language (`/id/`, `/en/`) is separate. Follow the steps in order.

1. **Folder and files.** Create `src/content/sentences/<code>/<category>.json` for each category (see "Content format" in `README.md`). The code is lowercase (`fr`, `vi`, `pt-br`, `zh-hans`; uppercase is rejected because Astro lowercases entry ids). Each file has `"lang": "<code>"` and ids `<code>-<category>-001`. The next build serves `/data/<code>/sentences.json` and the language switch lists it, named by `Intl.DisplayNames`.
2. **Text form.** Sentences must be Unicode NFC: an accented letter is one character, not a letter plus a combining mark (the build checks this for every language). Typing a sentence must be possible on the normal keyboard of that language, including through its usual input method (for example Telex for Vietnamese).
3. **Length range** (`TEXT_LENGTH` in `src/lib/content-rules.ts`). Without an entry the language uses the `en` range (`es`, `pt-br`, `fr` and `de` already have a starting entry, 58-196: the `en` range x 1.15). Add `<code>: [min, max]` when its sentences need another range; scripts in which one character carries more meaning (Chinese, Japanese) need a much shorter one.
4. **Difficulty threshold** (`DIFFICULTY_THRESHOLDS` in `src/lib/difficulty.ts`). Without an entry the language uses the `en` threshold (the draft languages have a starting entry, not measured: `es`, `pt-br`, `fr` 120, `de` 115). Write about 20 sentences, run `pnpm content:stats --scores`, set the threshold near the median score it prints (so about half the sentences are `easy`), then label every sentence with the level shown. Recalibrate as the corpus grows.
5. **Allowed characters** (`LANGUAGE_RULES` in the same file). Without an entry the language must be printable ASCII (`\x20-\x7E`), so any language with accents or another script fails the build until it has a rule. An entry is `{ allowedChar, hint, forbidden? }`: `allowedChar` is a regular expression for ONE allowed character (no `g` or `y` flag), `hint` tells authors what to do with a rejected character, and the optional `forbidden` is a list of `{ pattern, message }` for layout rules that one character cannot express (French: no space before `: ; ! ?`). `latinAccentRules(lowercase, hint, options)` in `content-rules.ts` builds an entry for a Latin language with accents (ASCII plus the letters, both cases). Include the space and only characters a person can type. Example for French: `fr: { allowedChar: /[\x20-\x7E\u00C0-\u00FF\u0152\u0153]/, hint: 'Use French letters only.' }`. Add a test case next to the entry and update `CONTENT_GUIDE.md` (section 2, "Typing comfort") with the characters that language allows.
6. **Keyboard layout** (`KEYBOARD_ROWS` in `src/features/stats/weak-keys.ts`). The heat map on the statistics page draws the letters in the layout of the sentence language. Without an entry the language uses QWERTY (`id`, `en`, `es`, `pt-br`); `fr` has AZERTY (`azertyuiop / qsdfghjklm / wxcvbn`) and `de` QWERTZ (`qwertzuiop / asdfghjkl / yxcvbnm`). For a language with another layout, add `<code>: ['row1', 'row2', 'row3']` (lowercase letters, each of the 26 once; a test checks that) and a case in `weak-keys.test.ts`. Accented letters are not drawn but are still counted and listed as weak keys.
7. **Fonts.** Lora (the typing font) already covers Latin with accents (latin and latin-ext), Vietnamese, and Cyrillic; the browser loads only the subsets a page uses, so there is nothing to configure. For a script Lora lacks, pick the matching Noto Serif package on Fontsource (for example `@fontsource-variable/noto-serif-devanagari`, `@fontsource-variable/noto-serif-jp`, `@fontsource/noto-serif-hebrew`, `@fontsource/noto-serif-thai`; for Arabic `@fontsource-variable/noto-naskh-arabic`), install it (note the dependency in the changelog), add it as another entry in `fonts` in `astro.config.mjs` with its own `cssVariable` and a `unicodeRange` for the script, render it with `<Font cssVariable="..." />` (no preload) in `BaseLayout.astro`, and put it first for that language with a rule such as `:lang(<code>) { font-family: var(--astro-font-<name>), var(--font-typing); }` in `global.css` (the typing text already carries `lang="<code>"`). Check the script in the browser: mark-heavy scripts need the caret and the per-character spans to keep working.
8. **Check.** Run `pnpm check && pnpm test:run && pnpm build`, confirm `dist/data/<code>/sentences.json` exists, and look at the typing area in light and dark mode at 390 px. For a language with accents also type a sentence by hand with the keyboard layout of that language (dead keys on Spanish, French and Portuguese layouts) on a desktop and on a phone: no false errors, no stuck cursor, and the Lora letters must not fall back to another font (the automated test only simulates input).

## Deploy

The site is static: `pnpm build` writes everything to `dist/`, and any static host can serve it. The recommended host is **Cloudflare Pages**: free for static sites, global CDN, automatic HTTPS, per-pull-request previews, custom headers through `public/_headers`, and nothing to migrate if you leave (it is just the `dist` folder). Netlify reads the same `_headers` file, so it works too.

**Setup on Cloudflare Pages** (Workers & Pages, Create, Pages, Connect to Git; the click-by-click guide for the repository owner is in [`MAINTAINING.md`](MAINTAINING.md)):

| Setting | Value |
| --- | --- |
| Production branch | `main` |
| Build command | `pnpm build` |
| Build output directory | `dist` |
| `NODE_VERSION` (environment variable) | `24` (the build image default, 22.23.4, also satisfies `engines`) |
| `PNPM_VERSION` (environment variable) | `12.15.0` (the build image's default pnpm is older and does not read `packageManager`) |
| `SITE_URL`, `PUBLIC_REPO_URL` | see "Environment variables" in `README.md`; set `SITE_URL` to the final public origin, or canonical links and the sitemap are left out |

Commit `pnpm-lock.yaml` first: the host installs from it.

**Security headers.** `public/_headers` is copied to `dist/_headers` and applied by the host (`pnpm dev` and `astro preview` ignore it). It sets, for every path, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, a minimal `Permissions-Policy` (camera, microphone, geolocation, payment, USB and interest-cohort all off; the site uses none of them), and `Content-Security-Policy: frame-ancestors 'none'`. Files under `/_astro/` carry a content hash in their name, so they are cached for a year as `immutable`; pages and `/data/*` use the host's default (always revalidated), so a new deploy shows at once.

**Content Security Policy for scripts, styles and everything else.** `security.csp` in `astro.config.mjs` turns on Astro's built-in CSP (stable since Astro 6). At build time Astro writes a `<meta http-equiv="content-security-policy">` into every page with `script-src 'self'` and `style-src 'self'` plus the SHA-256 hash of every script and style it bundles or inlines (island hydration, component styles), so no `unsafe-inline` is needed. The inline theme script (`THEME_INIT_SCRIPT`, see "Theme") is not bundled by Astro; `BaseLayout.astro` adds its hash with `Astro.csp.insertScriptHash`, computed by `lib/csp.ts` from the same constant that is rendered, so the two cannot drift apart. The `directives` list adds `default-src 'self'` and the same-origin rules for images, fonts, connections, the manifest, plus `object-src 'none'`, `frame-src 'none'`, `base-uri 'self'` and `form-action 'self'`. Nothing is loaded from another origin. Why a `<meta>` tag and not a header: the hashes change with every build, and a static `_headers` file cannot list them; a `<meta>` tag cannot carry `frame-ancestors`, which is why that one directive is in `_headers`. Known limits: a `<meta>` policy only applies to what comes after it in the page (the theme script, which we wrote, comes before it), and Astro's `<ClientRouter />` view transitions are not supported with CSP (the site does not use them). The site has no Markdown, so `markdown.syntaxHighlight` is `false` (Shiki's inline styles are incompatible with CSP, and Astro warns about it at every build); if Markdown with code is added later, use Prism. `astro dev` does not produce the policy (Vite's dev server cannot); check it with `pnpm build` and `pnpm preview`. `tests/e2e/csp.spec.ts` loads the pages in a real browser and fails on any violation, and checks that every inline script on a page has its hash in the policy.

**When a feature needs another origin**, add it to `security.csp.directives` (`connect-src`) and, for a script, to `scriptDirective.resources` (this list replaces Astro's default and does not include `'self'` unless you list it); the e2e test then shows whether the policy still holds. Analytics is the one case so far: `astro.config.mjs` takes both lists from `analyticsCspSources(token)` (`src/lib/analytics-config.ts`), so with no token the policy keeps `'self'` as the only source, and with a token it adds exactly `https://static.cloudflareinsights.com/beacon.min.js` (script) and `https://cloudflareinsights.com` (connect).

## Analytics

**Provider:** Cloudflare Web Analytics: free, no cookies, no personal data, and the same account as the recommended host. It is installed by hand (our own script tag), not through the Pages dashboard toggle, because the policy only allows the hosts of a manual install (`connect-src` needs `cloudflareinsights.com`; the dashboard's automatic injection would be blocked and, if it were allowed, would report to a different place). **Do not enable the automatic "Web Analytics" toggle on the Pages project**: only one beacon per page is supported and the injected one would be blocked by the CSP anyway.

**How it works** (`src/lib/analytics.ts`, pure parts tested): `BaseLayout.astro` runs `initAnalytics()` on every page. The beacon `<script type="module" src="https://static.cloudflareinsights.com/beacon.min.js?token=...">` is added at runtime only when **all** of these hold: a token is configured (`PUBLIC_ANALYTICS_CLOUDFLARE_TOKEN`), the build is a production build (`import.meta.env.PROD`, so never in `pnpm dev`), `navigator.doNotTrack` is not `"1"`/`"yes"`, and `navigator.globalPrivacyControl` is not `true`. A visitor who opted out never downloads the script. Nothing else is sent: no custom events (Cloudflare Web Analytics has none) and no WPM, text or other data from the app.

**Setup:** Cloudflare dashboard, Analytics & Logs, Web Analytics, Add a site (choose the manual JS snippet, not automatic setup), copy the `token` value, set `PUBLIC_ANALYTICS_CLOUDFLARE_TOKEN` in the Pages project's environment variables (and in `.env` only if you want to test a local `pnpm build` + `pnpm preview`), then redeploy. The token is public by nature (it is visible in the page source). **Privacy page:** it shows a different paragraph depending on whether a token was set at build time (`privacy.analyticsOn` / `privacy.analyticsOff`), so the page always matches what the build does; if you change provider, rewrite `analyticsOn`.

**Check:** open the site with a token build, DevTools, Network: one request to `beacon.min.js?token=...` and, after a moment, a POST to `cloudflareinsights.com/cdn-cgi/rum`; Console shows no CSP message. With Do Not Track on (or `navigator.globalPrivacyControl`), no request to Cloudflare appears. Ad blockers block the beacon, so the counts are a lower bound.

**After the first deploy, check:** open the site with the browser's developer tools (Network, then a page, then Headers) and confirm the headers above on `/id/` and the long cache on a file under `/_astro/`; the Console must show no "Content Security Policy" message; `curl -sI https://<your-domain>/id/` shows the response headers.
